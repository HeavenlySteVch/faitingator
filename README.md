# WoW Damage Parser

Приложение читает боевой журнал World of Warcraft (`WoWCombatLog.txt`) и разбивает его
на **заходы в подземелья**. Виден список заходов, а по клику на строку — детали:
состав группы, класс и характеристики каждого игрока, урон, исцеление, прерывания,
смерти и разбивка по способностям.

## Быстрый старт

1. **Включи расширенное логирование** (нужно для классов и характеристик) — в игре в чат:
   ```
   /console advancedCombatLogging 1
   ```
   Без него лог работает, но остаются только урон, исцеление, прерывания и смерти —
   события `COMBATANT_INFO` не пишутся. Если команды не хватает, попробуй ещё и
   галочку `Улучшить логирование боёв` в Настройки → Система → Сеть.
   Достаточно один раз: клиент сохраняет эту настройку между запусками.

2. **Настрой автозапись журнала** — чтобы не вводить `/combatlog` каждый раз
   (см. раздел [«Запись журнала без /combatlog»](#запись-журнала-без-combatlog)):
   запусти приложение, открой вкладку **«Инфо»** и нажми кнопку
   **«Установить автозапись журнала»**, затем полностью перезапусти игру.

3. **Пройди подземелье** (ключ, обычный инст, рейд).

4. **Обнови данные в приложении** — кнопка **«Загрузить»** или F5. Путь к журналу
   подставляется сам:
   ```
   C:\Firestorm\Battle for Azeroth Reforged\Logs\WoWCombatLog.txt
   ```
   (кнопка **«Обзор»** — если путь другой).

## Запись журнала без /combatlog

Команда `/combatlog` переключает запись журнала **только до выхода из игры**: клиент
не сохраняет эту настройку (в `WTF\Config.wtf` попадает `advancedCombatLogging`, а
`combatLogging` — нет). Поэтому после каждого запуска игры запись приходится включать
заново.

Решение — маленький аддон **AutoCombatLog**, который лежит в этом репозитории
(`addon/AutoCombatLog/`). Он при входе в игру и при загрузке мира проверяет состояние
записи и, если она выключена, включает её тем же способом, что и `/combatlog`. Заодно
выставляет `advancedCombatLogging` и запоминает добычу (см. вкладку «Добыча»).

Установка: вкладка **«Инфо»** → кнопка **«Установить автозапись журнала»**. Приложение
выведет папку игры из пути к журналу и скопирует аддон в
`<папка игры>\Interface\AddOns\AutoCombatLog`. Новые аддоны подхватываются при запуске,
поэтому игру нужно полностью перезапустить (для уже установленного аддона хватит
`/reload`).

Проверка в игре — команда `/acl`:

| Команда | Что делает |
|---|---|
| `/acl` | показывает, включена ли запись и расширенное логирование |
| `/acl now` | включает запись прямо сейчас |
| `/acl off` | выключает автозапись (запись придётся включать самому) |
| `/acl on` | снова включает автозапись (включена по умолчанию) |
| `/acl loot` | сколько записей о добыче собрано |
| `/acl score` | текущий рейтинг Mythic+ (Fio), который увидит приложение |
| `/acl probe` | диагностика: собрать в SavedVariables служебную информацию |

### Рейтинг Mythic+ (RIO / Fio)

В правом верхнем углу шапки показывается счёт Mythic+ — на Firestorm это **Fio**
(серверная панель `MythicScore`, команды `/mscore`, `/mps`).

Цифра берётся прямо из игры: панель держит её в `MythicScore.data.overall`, аддон
`AutoCombatLog` раз в минуту переписывает её в `AutoCombatLogDB.score`, а приложение
читает из SavedVariables там же, где добычу. Игра сохраняет файл при `/reload` или
выходе — приложение подхватывает изменение в течение минуты (или сразу по F5).
Проверить, что аддон видит рейтинг, можно командой `/acl score`.

Цвет цифры — по ступеням, как в Raider.IO: серый → белый → зелёный → синий →
фиолетовый → оранжевый → золотой. Пороги лежат в `classes.py` (`RIO_COLORS`) и
подобраны под масштаб Firestorm: один данж даёт ~230–380, полный набор — 3000–4500.

### Добыча

Добыча не попадает в боевой журнал, поэтому аддон слушает сообщения чата о полученных
предметах (`CHAT_MSG_LOOT`) и складывает их в `AutoCombatLogDB.loot`: время, игрок,
id и название предмета, качество, уровень предмета, зона и id инстанса. Список
ограничен 400 последними записями.

Игра пишет этот файл при `/reload` или выходе из игры:

```
<папка игры>\WTF\Account\<аккаунт>\SavedVariables\AutoCombatLog.lua
```

Приложение читает его при загрузке журнала и раскладывает предметы по заходам — по
времени (ключ заканчивается на `CHALLENGE_MODE_END`, а лут падает уже после него) и по
названию подземелья. Поэтому после ключа достаточно сделать `/reload` и нажать F5.

Можно поставить аддон и вручную: скопируй папку `addon\AutoCombatLog` в
`<папка игры>\Interface\AddOns\`.

Альтернативы, если аддон ставить не хочется:

- макрос с `/combatlog` на панель — одно нажатие вместо набора команды;
- дописать `SET combatLogging "1"` в `WTF\Config.wtf` при **закрытой** игре: работать
  может не везде, так как клиент считает эту настройку несохраняемой.

Запись идёт всегда, в том числе в открытом мире, поэтому файл журнала растёт. Приложению
это не мешает (открытый мир отсекается фильтром «Только подземелья»), но при желании
старые записи можно удалять — при следующем запуске игры файл начнётся заново.

## Как выглядит интерфейс

Сверху — таблица **заходов**, снизу — вкладки деталей выбранного захода.

### Вкладка «Заходы»

| Колонка | Значение |
|---|---|
| Дата | Дата и время начала захода |
| Подземелье | Название зоны |
| Игроки в группе | Кто участвовал — имена цветом класса |
| Ключ | Уровень кейса (`+10`) |
| Результат | `+1` / `+2` / `+3` / `провал` — на сколько плюсов закрыли |
| Время | Длительность прохождения |
| Таймер | Лимит времени подземелья |
| Урон группы | Суммарный урон всех участников |

Строка захода красится по уровню ключа: **M0 — синий**, **+2 — зелёный**, дальше
оттенок плавно уходит через жёлтый к **красному на +20**, а ключи выше 20 — **чёрные**.
Имена игроков в списке подсвечены цветом класса и идут по ролям: сначала **танк**,
потом **лекарь**, затем **дд** (внутри роли — по урону); «прохожие» (кто зашёл в лог,
но ничего не сделал и о ком нет данных) в группу не попадают.

Один заход — одна строка, даже если клиент присылает смену подзоны внутри того же
инстанса (в «Осаде Боралуса» это «Осада боралусского моста»): такие переходы
объединяются, поэтому урон и время ключа не распадаются на куски. Повторный
`CHALLENGE_MODE_START` того же ключа через пару секунд (особенность Firestorm) тоже
не обнуляет уже накопленный урон.

Фильтр **«Только подземелья»** (включён по умолчанию) прячет то, что происходило
в открытом мире — в истории остаются только инстансы: мифик+, обычные подземелья и
рейды. Галочка **«Только ключи»** оставляет только мифик+, а строка поиска ищет по
названию подземелья.

### Вкладка «Группа»

Кто был в группе: имя, iLvl, специализация, урон, ДПС, доля от общего урона,
исцеление, число прерываний кастов и смертей.

ДПС и ХПС считаются от **общего времени захода** — одинакового для всех участников
(как в Details!): урон делится на реально прошедшее время от старта ключа до финиша.
Раньше делили на «активные секунды» каждого игрока отдельно, и при почти равном
уроне ДПС расходился на 10–20%.

Столбец **«Урон»** заполняется цветом как в дпс-метрах: у самого результативного
игрока полоса заполнена целиком, у остальных — на его долю от лучшего результата
(например, 43% — значит этот игрок нанёс 43% урона от лидера). Цвет полосы —
цвет класса. Класс отдельной колонкой не выводится: имя игрока и так покрашено
цветом класса, как в игре.

Специализация берётся из `COMBATANT_INFO`, но в нём на Firestorm записан
**лут-спек** (специализация для добычи), который часто не совпадает с боевой.
Поэтому специализация дополнительно уточняется по использованным способностям:
например, танк-монах с лут-спеком «Танцующий с ветром» определяется как хмелевар,
а «ледяной» маг на самом деле может играть тайной магией.

### Вкладка «Характеристики»

iLvl, сила, ловкость, выносливость, интеллект, броня, крит, скорость, искусность
и универсальность — из события `COMBATANT_INFO` (поэтому требуется шаг 1 выше).
Значения выводятся теми же цветами, что и классы в игре.

### Вкладка «Способности»

Выбери игрока из списка — увидишь разбивку его урона по способностям:
урон, доля, число ударов, критов и самый сильный удар.

### Вкладка «Добыча»

Кому что выпало с финального сундука: игрок (цветом класса), предмет (цветом
качества), его уровень, качество и время получения. Данные берутся из аддона
`AutoCombatLog` — без него вкладка пустая и подсказывает, что делать.

### Вкладка «Инфо»

Напоминание обо всех пунктах выше и кнопка **«Установить автозапись журнала»** —
копирует аддон `AutoCombatLog` в игру, чтобы запись включалась сама. Рядом показано,
установлен ли аддон уже.

## Оформление

Тёмная тема «графит»: панели-карточки с тонкими рамками, акцентный синий, текст —
Segoe UI, числа — Consolas (цифры стоят ровно в столбик).

- В шапке видно, в каком формате журнал (обычный или расширенный), есть ли в нём
  `COMBATANT_INFO` и сколько нашлось заходов.
- В таблицах подсвечивается строка под курсором, а у выбранного захода слева
  появляется акцентная полоса.
- Полоса урона заливается градиентом в цвете класса; у лучшего игрока слева от имени
  стоит золотая ★, имя при этом остаётся цветом класса.
- Число поверх полосы рисуется с тенью, поэтому читается и на тёмном фоне, и на
  светлой части полосы.
- Иконка окна и панели задач — золотой «камень-ключ» на тёмной плитке; рисуется
  скриптом `tools/make_icon.py` (PIL) в `icon.ico` и `icon.png`.

Всё оформление собрано в начале `gui.py`: цвета — константы (`APP_BG`, `CARD`,
`ACCENT`, ...), шрифты — функция `make_fonts()`, цвет строки захода по уровню ключа —
`key_level_color()`.

## Как считаются урон и iLvl

- **Урон считается только по противникам.** «Пошатывание» хмелевара и другие
  эффекты, бьющие по самому игроку, полученным уроном не считаются — иначе танк
  «наносил» бы лишние миллионы. Из-за этого цифры совпадают с аддонами вроде
  Details!, а не завышаются.
- **Урон питомцев и стражей** (армия мёртвых, вурдалак, элементали, призванные
  демоны) приписывается владельцу. Владелец берётся из расширенного блока журнала:
  в любой строке, где питомец — цель, рядом с его идентификатором записан
  идентификатор хозяина. Дополнительно учитывается событие призыва (`SPELL_SUMMON`)
  и «свои» ауры, которые накладываются только на своего питомца. Если владельца
  определить нельзя, урон питомца не приписывается никому.
  На Firestorm питомцы бывают двух видов — `Pet-…` (флаг `0x1000`) и `Creature-…`
  с флагом стража `0x2000`; у охотника со вторым животным урон второго питомца
  приходит именно как `Creature-…`, раньше он терялся.
- **Учёт начинается со старта ключа**, а не с входа в подземелье: мусор, убитый до
  вставки ключа, в статистику не попадает — так же считает игра и Details!.
- **iLvl считается как в игре** — без рубашки и табарда (у табардов BfA уровень
  предмета 120, из-за чего средний iLvl занижался, например 359 вместо 374).
  Предметы, чей уровень резко ниже остальных, отбрасываются.

## Если что-то не работает

- **«Файл не найден»** — журнал ещё не создан: запись не была включена. Поставь аддон
  автозаписи (см. [«Запись журнала без /combatlog»](#запись-журнала-без-combatlog)) или
  введи `/combatlog` в игре и пройди подземелье.
- **Записи нет, хотя аддон установлен** — игру нужно полностью перезапустить после
  установки аддона; проверь статус командой `/acl` в игре (и что аддон включён в списке
  аддонов на экране выбора персонажа).
- **«Характеристики недоступны»** — не включено расширенное логирование.
- **В истории нет захода** — заход был в открытом мире (город, локация). Сними галочку
  «Только подземелья», чтобы увидеть всё, включая открытый мир.
- **Класс игрока определён неверно** — класс берётся из `COMBATANT_INFO` по
  идентификатору специализации; без расширенного логирования он угадывается по
  использованным способностям и может ошибаться.
- **Специализация не та** — в логе Firestorm `COMBATANT_INFO` содержит лут-спек.
  Приложение уточняет специализацию по способностям (`SPEC_SPELLS` в `classes.py`),
  список можно дополнять.
- **Бонус = «—»** — таймер для этого подземелья неизвестен. Таймеры прописаны в
  `classes.py` (`DUNGEON_TIMERS` по названию и `DUNGEON_TIMERS_BY_ID` по номеру ключа);
  значения взяты из клиентской таблицы `MapChallengeMode` (build 8.3.7.35662), можно
  добавить своё подземелье. Бонус считается по времени из `CHALLENGE_MODE_END`, в которое
  игра уже включила штраф 5 секунд за каждую смерть.
- **Вкладка «Добыча» пустая** — нет файла
  `WTF\Account\<аккаунт>\SavedVariables\AutoCombatLog.lua`: аддон не установлен или игра
  ещё не писала сохранения. Поставь аддон кнопкой на вкладке «Инфо» (если он уже стоял,
  приложение подскажет «аддон устарел»), сделай `/reload` в игре и нажми F5. Проверка:
  `/acl loot` в игре показывает число собранных записей.
- **Добыча попала не в тот заход** — привязка идёт по времени и названию подземелья;
  если ключ закрыт давно, а лут забрали сильно позже, запись может не найтись.
